# RelayPine 用量与额度说明

当前范围为超级管理员自用验证与公开候补名单。Stripe 收款能力已取消，没有在线充值、退款、订阅或外部付款通知处理。保留用量计量及账本是为了控制调用成本，不代表网站已对候补用户开放付费服务。

## 账户与准入

唯一超级管理员为 `ufcenterxyz@gmail.com`，服务端预置账号并验证邮箱的一次性验证码。其他访客验证邮箱后只进入 waitlist，不创建工作区、钱包、访问 Key 或登录会话。历史非管理员账号也不能继续访问。将来邀请开放需要单独设计明确的准入流程。

## 两种预算

| 数据 | 用途 |
| --- | --- |
| 工作区余额与请求预留 | 控制已授权调用的可用额度，记录每个请求的用量结算 |
| 上游凭据预算与成本预留 | 限制每把上游 Key 在本网关产生的成本 |

金额使用整数 micro-USD，`1 USD = 1,000,000 micro-USD`。每百万 Token 价格独立配置输入、输出、缓存读取和缓存写入，调用时固定价格版本。不同币种不混算；当前只使用 USD。

可用余额等于账面余额减活跃预留。上游预算剩余量等于配置上限减已花费及已预留；上游 `budget_micros=0` 表示无本地成本上限，不等于实际余额为零或无限供应商余额。

## 预留与结算

请求发出前保守预留工作区额度和上游预算；Redis 原子脚本控制速率、共享组与并发。收到可信用量后，在 MySQL 事务中按请求快照幂等结算，释放多余预留。工作区记录金额不超过该请求预留。

平台或上游失败时不扣工作区费用，但已发生或未知的上游成本仍保留核对。客户端取消且最终用量已确认时按实际用量结算。未知用量的工作区预留最多保留 24 小时；超时释放后，晚到证据只调整上游成本，不追扣已终结请求。

当前不做跨协议转换，不接受无法可靠建立计量上界的额外收费能力。响应开始发送后不会自动切换 Key 重放生成。

## 内部额度调整

超级管理员可记录带理由的内部额度调整。操作必须关联操作者、工作区、金额和唯一参考，并在同一事务中更新余额和写入账本。它不会扣银行卡、调用支付服务或产生真实收款凭证。

`ledger_entries` 是当前实现的追加式明细，并非完整财务总账。历史支付相关表保留供追溯；取消支付功能不会删除历史资金记录。当前 API 不再暴露 Checkout、退款或 Stripe webhook，后台也不处理旧支付事件。
