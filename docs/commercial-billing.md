# RelayPine 用量与额度说明

用户通过邮箱验证码获得独立工作区，初始钱包余额为零。独立管理站只有 `SUPERADMIN_EMAIL` 指定的管理员可进入，管理上游、参考价格和带理由的额度调整。没有 Stripe、在线充值、退款或支付回调。

## 参考价格与模型启用

批量导入先从官方公开价表匹配模型，默认以标准文本参考价同时设置售价和成本价，比例为 1:1。模型列表 API 本身不返回单价。每次匹配保留来源与检查时间；管理员使用“更新参考价格”先预览差异，再选中应用。版本变化会阻止覆盖并要求重新预览。

官方参考价仅适用于对应官方上游，不代表第三方服务、账号折扣或合同价格。第三方 host 需要显式配置自己的销售和成本价格。无法精确匹配的型号不能当作免费，保持禁用等待配置。启用的模型要求 `metered` 以及正数输入/输出售价和成本价。

旧模型补价只影响后续请求。历史 `usage_only` 请求保持原始快照，不补扣、不增加余额、不改账本。更新价格也不改变模型权限、Key 限流或上游预算。

## 两种预算

| 数据 | 用途 |
| --- | --- |
| 工作区余额与请求预留 | 客户可用额度及每个请求的实际扣费 |
| 上游凭据预算与成本预留 | 每把上游 Key 在本网关产生的成本上限 |

金额使用整数 micro-USD，`1 USD = 1,000,000 micro-USD`。每百万 Token 分别配置输入、输出、缓存读取和缓存写入价格；请求开始时固定完整价格快照和版本。当前只使用 USD。

可用余额为账面余额减活跃预留。上游预算剩余量为配置上限减已花费及已预留；上游 `budget_micros=0` 表示无本地成本上限，不等于供应商实际余额无限。管理员自己的 API 调用同样需要 RelayPine 余额。

## 预留与结算

发出请求前保守预留客户额度和上游预算；Redis 原子脚本控制速率、共享组与并发。收到可信用量后，在 MySQL 事务内按请求快照幂等结算，扣减余额、写入费用账本并释放多余预留。客户扣款不超过该请求预留。

平台或上游失败不扣客户费用，已发生或未知的上游成本仍保留核对。客户端取消但最终用量已确认时，按实际用量结算。未知用量的客户预留最多保留 24 小时；超时释放后，晚到证据只调整上游成本，不追扣已终结请求。

现有标准服务等级、缓存条件和输出上限继续执行，未支持的额外收费能力仍被拒绝。响应开始发送后不会自动换 Key 重放生成。

### Anthropic 图片输入的保守预留

Messages 与 `count_tokens` 仅接受 user content（含 user 的 `tool_result.content`）中的内联 base64 静态 PNG/JPEG；图片 URL、上传文件引用、其他图片格式和 OpenAI 图片输入仍不支持。整个 JSON 请求仍限 2 MiB；本地最多 20 张、每轴 8,000 像素、单图 16,000,000 像素、总计 32,000,000 像素，所有限制同时执行。

输入上界按下式计算，`ceil` 表示向上取整，宽高来自已验证图片：

```text
文本及封装上界 = 2 × (原请求体字节数 − 已验证图片 base64 逻辑字节数之和) + 4096
每图上界 = 2 × ceil(width / 28) × ceil(height / 28) + 256
输入上界 = 文本及封装上界 + 各图片上界之和
```

只扣除协议指定图片位置中验证通过的 base64 字符串逻辑长度。文本或工具参数中相似的字符串不会被扣除；JSON 转义增加的请求字节仍留在保守估算中。HTTP 2 MiB 限制始终按完整原请求体计算，不扣除图片。

同一输入上界用于参考价上下文检查、TPM 准入和金额预留；生成请求还结合输出上限预留客户额度及上游成本。这是本网关的保守预算，不是上游 tokenizer 的精确结果或新增按图片收费的费率。最终按可信上游 usage 和请求价格快照结算，释放多余预留；已有未知用量处理规则不变。图片数据原样转发，不为估算重新压缩或写入请求日志。

客户端显式请求 `count_tokens` 时不预留金额、不扣 RelayPine 余额，仍执行模型权限、上下文、RPM/TPM 与并发等检查。网关不会为每个生成请求自动发起额外的 `count_tokens` 调用。编码前缩小尺寸或压缩图片可减少传输体积；其中缩小像素尺寸也会降低本地图片输入上界。

## 备用通道

管理员可在 Upstreams 配置 OpenRouter 或 ZenMux 备用通道。某个模型的所有官方通道都无法处理请求（Key 被拒、余额不足、限流、服务端故障或请求未能发出）时，Chat Completions 和 Messages 依次改走备用通道，每个请求最多尝试三条通道。只有上游在产生任何输出前明确拒绝的尝试才会换路；被拒绝的尝试按零上游成本关闭，其上游成本预留在同一事务中转到下一把凭据。客户预留和价格快照保持不变，客户最多按原售价扣费一次。

备用通道没有本地金额上限，消费上限在服务商账户或 Key 上设置。备用通道的上游成本按模型的上游成本价估算记录，不读取服务商发票。HTTP 401、402、403、429 和 5xx 视为明确拒绝且无上游成本；结果未知（请求已发出后中断）的尝试不重放，上游成本仍保留核对。

## 内部额度调整

管理员记录正数额度调整时必须填写原因、工作区和唯一业务参考，服务端同时记录操作者并在一个事务内更新余额和追加账本。这不会扣银行卡、调用支付服务或向上游充值，也不是外部收款凭证。

`ledger_entries` 是追加式用量明细，不是完整财务总账。历史支付相关表保留供追溯；取消支付功能不会删除历史资金记录，也不会继续处理旧支付事件。
