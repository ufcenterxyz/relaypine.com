# LLM Relay 开发阶段与验收标准

本计划按依赖顺序推进。当前完成的是规划阶段，其余阶段尚未实施。第一版按内部使用交付，暂不包含对外销售和客户充值。

## 阶段 0 项目基线

已完成：需求拆解、协议范围、对象模型、调度规则、预算一致性、代理与流式边界、验收清单。

进入实现时，建立 Go gateway 和 Next.js/HeroUI console；核对依赖版本；提供本地 MySQL/Redis Compose、配置样例、格式检查、类型检查和 CI。使用 mock 上游完成大多数测试，不需要把真实 API Key 提交到仓库。

## 阶段 1 可用的原生中转

交付上游/Key/代理配置、访问 Key 鉴权、官方默认 host、自定义 Endpoint、Claude Messages 与 OpenAI Chat Completions/Responses 的 JSON 和 SSE。此阶段 Responses 只提供明确标识的无状态模式；资源归属完成后，在阶段 2 开放 previous_response_id 和 GET/DELETE。

验收：

- 两种协议的官方与兼容 mock 上游均可用；路径前缀不重复或覆盖 host。
- 认证头只发送给绑定上游，客户端不能注入另一个上游地址。
- 流式事件、工具调用和未知字段保留；首事件及时输出，客户端取消会中断上游。
- SOCKS5 认证和连通性可验证，代理不可用时没有直连流量。
- 上游重定向不会泄漏 Key；请求日志和错误日志无 Key 或代理密码。
- 明确拒绝不在一期范围的端点、资源引用和独立计费能力。

## 阶段 2 多 Key 调度与预算

交付共享限流组、三种路由策略、RPM/TPM/并发限制、冷却与熔断、预算预留和幂等结算、Responses 归属绑定。

验收：

- 20 个并发请求竞争仅 5 个剩余槽位时最多放行 5 个。
- 同账号多个 Key 消耗同一组限流；一个 Key 的 429 能冷却受影响的共享组。
- 配额优先不把余额未知/过期的 Key 纳入余额排序，仅允许它们进入明确配置的备用路线；已达 RPM 上限的 Key 不放行。归一化负载体现不同 Key 的容量。
- 两实例同时预留预算不透支；金额使用定点精度。
- 预算预留成功但 Redis 抢占失败能补偿；发送前后崩溃恢复不会重复扣款或无条件退款。
- 跨预算周期完成仍正确结算到原期间；重置不删除未完成预留。恢复任务不能与活跃发送协程竞态退款。
- 重复完成通知只结算一次；每次重试有独立尝试账目。
- SSE 中途报错或断开不换 Key 重新生成；累计 usage 不重复累加。
- 不同访问 Key 无法引用对方 response ID；状态请求不会跨 Endpoint 随机路由。
- response ID 在客户端可见之前归属已落库，立即续接不产生映射竞态；映射写入失败不暴露该 ID。
- Redis/预算数据库故障时拒绝新的收费请求，既有流按可用状态收尾并保留恢复证据。

## 阶段 3 管理后台与上线准备

交付管理员登录、Provider/Key/额度/代理/路由/业务访问 Key 的管理、请求日志、用量看板、配置审计和基础健康检查。所有管理 API 服务端鉴权。

验收：

- 在后台新增官方上游、录入多个 Key、绑定共享额度组、设置代理、生成业务访问 Key，再从 SDK 发请求的闭环可用。
- 界面能解释本次为什么选择某 Key，以及未选择其他 Key 的原因。
- 显示真实值/估算值、币种、余额更新时间与待核对费用，不展示虚构余额。
- 表单、空状态、加载、错误、删除确认、键盘操作、桌面和移动视图完成验证。
- 网关在持续 SSE 请求期间滚动重启可排空；入口没有流缓冲，超时策略经过验证。
- 完成指定真实供应商与代理的最小烟测后，才声明对应生产兼容；没有凭据时报告 mock 验证与真实验证的边界。

## 后续阶段

按真实需要添加供应商余额插件、Admin Usage/Cost 对账、自动限额同步、告警渠道、延迟自适应、更多资源 API、Realtime/WebSocket、团队权限及多租户计费。跨协议转换作为独立能力实现并标注能力损失，不影响原生协议的正确性。

对外售卖时再引入客户、充值、套餐、销售价格与上游成本分账；当前账本保留扩展点，但不把支付系统塞进第一版。

## 实施前默认选择

| 项目 | 默认 |
| --- | --- |
| 项目名 | LLM Relay / `llm-relay`，可更名 |
| 使用范围 | 内部多个业务共用 |
| 路由策略 | 负载优先，支持切换额度优先或均衡 |
| 额度权威来源 | 本地预算账本；上游余额另标来源 |
| ss5 | SOCKS5，可认证，出口失败不直连 |
| 金额 | 同币种定点计价；初始 USD，保留币种字段 |
| 预算周期 | 明确保存时区，默认 Asia/Singapore |
| 日志 | 默认只存元信息，保留时长可配置 |
| 部署 | 开发先 Docker Compose，生产可接现有 TKE 流程 |

这些默认不需要阻止基础开发。上线验收时需要真实上游、模型、Key、共享限额及代理配置；通过后台或部署 Secret 注入，不写入文档或代码。
