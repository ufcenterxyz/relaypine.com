# RelayPine 当前范围与验收

当前产品采用超级管理员 + waitlist 模式。每个部署由 `SUPERADMIN_EMAIL` 指定唯一管理员，其他人只登记候补；Stripe 充值与支付相关能力已从当前范围移除。

## 当前实现

- Next.js / HeroUI 官网与控制台，深浅色和移动端布局，代码实现的可交互路由说明。
- 邮箱验证码登录的固定超级管理员、验证邮箱后持久化的去重候补名单、管理员名单查询。
- 官方与兼容 Claude / OpenAI host、多 Key、共享 RPM/TPM/并发限制和独立 SOCKS5。
- JSON / SSE 原生转发、Responses 归属校验、路由策略、请求前额度预留与用量结算。
- MySQL / Redis 本地环境，Go 单元及集成测试，前端类型检查、lint 和生产构建。

## 访问控制验收

1. 候补提交必须完成邮箱验证，只保存联系资料；重复邮箱不增加第二条记录。
2. 旧注册入口不能创建账号或会话，请求中的 operator 等字段不能提升权限。
3. 管理员邮箱必须通过一次性验证码验证；没有密码回退，旧密码会话失效，原有同邮箱普通账号不能带着旧凭据直接升级。
4. 非管理员旧会话、访问 Key、伪造管理标记均被拒绝。
5. 只有管理员可读取候补名单及基础设施配置。
6. Checkout、退款、Stripe webhook 不再可用；保留历史数据，不执行破坏性删表。
7. 验证码过期、尝试次数、重发冷却和原子消费由服务端执行；邮件发送或 Redis 故障不发放会话。

## 转发与预算验收

保留现有原生协议、共享限流、SOCKS5 失败关闭、请求预算预留与幂等结算测试。调整准入模式不降低上游预算约束，也不自动给管理员无限余额。

## 公网开放前

配置邮件发信服务、真实上游和代理，验证邮件投递、SSE、域名 TLS、备份恢复、监控和安全凭据注入。候补名单只通过邮件验证邮箱，不自动放行；将来开放普通账户需新增明确的邀请/审批流程。Stripe 或其他收款渠道不属于当前交付要求。
